SolsticeのQt Widgetsを維持し、配色、ドッカー見出し、ドキュメントタブ、
ツールバーから段階的に見た目を整える。描画作業の情報密度と既存操作を保ち、
小さな変更で画面全体の統一感を改善することを目的とする。

本書はユーザーと実装担当者が対象範囲・優先順位・完了条件を共有するための計画である。
初回の推奨範囲はフェーズ0〜2。共通部品の全面的な調整は、その結果を見て判断する。
以下の色・寸法・実装方式は提案であり、確定済みの仕様ではない。

## 現状と確認範囲

| 項目 | 確認した構成 | 計画への影響 |
| --- | --- | --- |
| UI基盤 | C++のQt Widgets、Qt Designerのフォーム、KDE系部品 | 既存部品とレイアウトを活用できる |
| 部品の描画 | 起動時と設定メニューでQtスタイルを選択。Breeze・Fusion等を扱う | 配色変更と形状変更を分ける |
| 配色 | ThemeManagerが `.colors` を読み、QPaletteに反映 | 既存テーマを残して追加テーマを作れる |
| 保存済み設定 | 調査時の `kritarc` は `Theme=Krita darker`。`widgetStyle` の明示設定なし | 実行中のスタイルはフェーズ0で確認する |
| アイコン | Breeze系とKrita独自のリソース。背景に応じた明暗の切替あり | 既存のアイコン名と読込経路を維持する |
| 独自部品 | ドッカー見出し、数値入力等に個別実装あり | QSSだけで全体を統一できるとは限らない |
| QML | SVGテキストツールとテキストプロパティ等で使用 | Widgets向け変更の適用範囲外として別途確認する |

現状調査はソースコードと保存済み設定に基づく。実行画面の撮影、実際のQtバージョン、
スタイルプラグインの同梱状況、表示倍率ごとの見た目は未確認である。
リポジトリがQt 5とQt 6のビルド分岐を持つことだけで、使用中のバージョンを断定しない。

## 目指す見た目

絵の色判断を妨げにくい無彩色の背景を基調に、面の明暗と控えめな境界線で領域を分ける。
アクセント色は選択・フォーカス等に絞り、立体的な縁取りを抑える。
大きな余白を一律に加えず、現在のキャンバス面積と操作部品の見つけやすさを保つ。

| 要素 | 初期案 | 調整基準 |
| --- | --- | --- |
| 背景 | ウィンドウ、パネル、入力欄を無彩色の3段階で区別 | 境界が見えること。純黒への一律変更はしない |
| 文字 | 本文、補助、無効の役割を統一 | 日本語の小さい文字でも読みやすいこと |
| アクセント | 低彩度の青系を初期候補とし、選択とフォーカスに使用 | 選択・ホバー・無効が混同されないこと |
| 境界線 | 原則1論理pxを基準に濃さを調整 | 高DPIで線が欠けたり二重になったりしないこと |
| 角丸 | ボタン・入力欄は2〜4論理pxを初期候補とする | 小さな部品の表示領域を圧迫しないこと |
| 余白 | 既存寸法を出発点に、同種部品の余白を揃える | 狭いドッカーで項目が切れないこと |
| フォント | OSと既存のユーザー設定を尊重 | 強制置換や一律拡大を避ける |

数値は100%表示での試作基準であり、端末の物理ピクセル数として固定しない。
具体的な色コードと最終寸法は、実画面の比較後に決定する。

## 対象範囲

初回は追加のダーク配色、ドッカー見出し、ドキュメントタブ、ツールバーを対象とする。
既存テーマやスタイルの選択を維持し、明るいテーマとの併用でも表示を壊さない。

後続候補は、ボタン・入力欄・チェックボックス等の共通部品、アイコンのサイズと線幅、
独自部品とQML側の見た目の調整である。

UI基盤の全面移行、メニュー構成の再設計、ドッカー配置の強制変更、
GPUエンジンやキャンバス描画処理の変更は対象外。
アプリのロゴ、スプラッシュ、ファイルアイコンの最終制作は
[ビジュアルブランディング計画](solstice-visual-branding-todo.md)で扱う。
現在のグレーの仮素材は本計画で置き換えない。

| スタイル設定 | `kritarc` に `widgetStyle` なし | 保存済み設定 |
| 配色テーマ | `Theme=Krita darker` | 保存済み設定 |
| フォント | `use_custom_system_font=true`、`custom_system_font=Segoe UI`、`custom_font_size=12` | 保存済み設定 |
| 表示 | 3840x2160のモニター3台、Windowsの表示倍率125%（120 DPI） | Win32 API、`AppliedDPI` |
| 高DPI設定 | `EnableHiDPI` は既定（有効）、`EnableHiDPIFractionalScaling` は未設定 | `krita/main.cc`、保存済み設定 |

使用スタイルの根拠: `KisApplication` は起動時のスタイル（Windowsでは
windows11）が許可リスト（haiku／macos／breeze／fusion）に無い場合、順に
`setStyle` を試す。Breezeは同梱されていないため、Fusionになる。`widgetStyle`
の設定が無いため、それ以上の上書きはない。`KisMainWindow` のスタイル
メニューも許可リストで絞るため、選べるのはFusionだけと見込まれる。

したがって、フェーズ3の基準候補であるFusionは、すでに既定の外観である。
配色は `.colors` テーマで、形状はFusionで決まっている。フェーズ1の追加
テーマは、現在の `Krita darker` との比較から始める。

### フェーズ1の試作（Solstice Dark）

`krita/data/themes/SolsticeDark.colors` を追加し、`CMakeLists.txt` の
インストール対象に加えた。テーマ一覧は `color-schemes/*.colors` を走査する
ため、コードの変更はない。既存テーマのファイルと名前は変更していない。

| 役割 | Krita darker | Solstice Dark（試作） |
| --- | --- | --- |
| ウィンドウ・ドッカー | 50,50,50 | 40,40,43 |
| 入力欄・一覧 | 28,28,28 | 30,30,33 |
| 一覧の交互行 | 36,35,35 | 36,36,39 |
| ボタン | 45,45,45 | 50,50,54 |
| 本文 | 235,235,235 | 224,224,228 |
| 無効・補助 | 120,119,117 | 128,128,134 |
| 選択 | 83,114,142 | 70,108,150 |
| フォーカス・ホバー | 160,160,160／176,176,176 | 98,140,188／122,162,206 |
| ツールチップ | 80,80,80 | 58,58,62 |

意図: ウィンドウ・入力欄・ボタンを無彩色の3段階で分け、ボタンを
ウィンドウより明るくして押せる部品を見分けやすくする。フォーカスと
ホバーだけを低彩度の青にし、選択と区別する。わずかに青みのある灰色は、
絵の色判断を妨げない範囲として選んだ。値は比較前の初期案である。

導入: CMakeを再構成し、`krita/data/themes` のインストール処理で
`_install/share/color-schemes/SolsticeDark.colors` に配置した。
切替は「設定 → テーマ」から行う。元に戻すときは `Krita darker` を選ぶ。

確認事項（ユーザー）: 通常・ホバー・押下・選択・無効の見分け、日本語の
小さい文字、スライダー、Quick Access等の独自UI、テーマの往復切替で旧配色が
残らないこと。

### フェーズ2の実装（Solstice interface）

設定: 「設定 → Solsticeの設定 → General → Window」の末尾に、チェックボックス
「Solstice interface (docker titles, document tabs, toolbars)」をコードで追加した
（`.ui` は変更していない）。保存先は `kritarc` の `Solstice/ModernInterface`、
既定はオフ。オフのときは従来と同じ描画・寸法になる。OKで閉じると
`KisConfigNotifier::configChanged()` → `KisMainWindow::configChanged()` →
`customizeTabBar()` の既存経路で反映される。テーマ変更時も `customizeTabBar()`
が呼ばれるため、色はテーマに追従する。

| 部品 | 変更内容 | 実装箇所 |
| --- | --- | --- |
| ドッカー見出し | 見出しの帯（本文色6%を混ぜたウィンドウ色）と下端の1px線（同16%）、余白を左右6／4px・上下3pxに拡大。スタイルの `CE_DockWidgetTitle` 描画は省略 | `KoDockWidgetTitleBar`: 静的フラグ `setSolsticeLookEnabled()`、`updateSolsticeLook()`、`paintEvent()` |
| 文書タブ | タブをタイトル幅に（`setExpanding(false)`）、選択中は明るい面と選択色の下線2px、非選択は本文色62%の文字、境界1px、ホバー面 | `KisMainWindow::customizeTabBar()` の既存QSSに追加。閉じるボタンのQSSは従来どおり |
| ツールバー | 下端の1px線、余白2／4px、区切り線を線色で表示 | 同上、各 `KisToolBar` にQSSを設定（オフでは空のQSSに戻す） |

フラグはライブラリの下位層（`libs/widgets`）にあるため、`KisConfig` は読まず、
`KisMainWindow` のコンストラクタ（ドッカー作成前）と `customizeTabBar()` が
設定する。既存のドッカーは `customizeTabBar()` の中で `updateSolsticeLook()`
を呼んで更新する。

確認事項（ユーザー）: オン／オフの往復、テーマ切替、ドッカーの浮動・タブ化・
狭幅・ロック、文書タブの切替・並べ替え・閉じる・未保存表示、ツールバーの
ボタンとツールバー内のスライダー・コンボボックスの見た目と操作。

ユーザー確認（2026年10月7日）: 問題なし。変更後の画面は
`<krita-dev-root>\ui-images\after` にある（`image3.jpg`: Solstice DarkとSolstice
interfaceを有効にした描画画面、Asset Libraryとブラシエディターを含む。
`image3(1).jpg`: 設定ダイアログ）。変更前の `before` と同じ条件で撮影されている。

未確認・制限: 125%以外の表示倍率。ツールバーへのQSSは子ウィジェットにも
スタイルシート描画を適用するため、ツールバー内の独自部品の見た目が変わる
可能性がある（実機で確認する）。ドッカーをタブ化したときのタブ（QMainWindow
のドッカータブ）は対象外。

### フェーズ3の実装（Solsticeスタイル）

`libs/widgetutils/KisSolsticeStyle.*`: Fusionを基底とするQProxyStyle。
描画だけを変え、寸法（pixelMetric、sizeFromContents、subControlRect）は
Fusionのまま。レイアウトは変わらない。

| 部品 | 描画 |
| --- | --- |
| プッシュボタン（`PE_PanelButtonCommand`） | 角丸3px、ボタン色の面、本文色20%の1px枠。ホバーで明るく、押下で暗く、トグルのオンは選択色35%、フォーカス時は枠を選択色に |
| ツールボタン（`PE_PanelButtonTool`） | 自動浮き上がりのボタンはホバー・押下・オンのときだけ角丸の面。オンは選択色40%（ホバー50%）。ツールボックスの選択中ツールもこれで示す |
| 入力欄の枠（`PE_PanelLineEdit`、枠幅1以上のみ） | 角丸、基本色の面、本文色20%の枠、ホバー32%、フォーカスで選択色。スピンボックスやコンボボックス内の入力欄はFusionのまま |
| チェックボックス・ラジオボタン | 角丸2.5pxの四角／円。オンは選択色で塗り、白いチェック（中間状態は横線）、ラジオは選択色の点。ホバーで枠が選択色。項目ビューのチェックも同じ描画になる |
| メニュー項目（`CE_MenuItem`） | 選択中の項目を左右2px内側の角丸の選択色で示し、文字はハイライト文字色。Fusionには非選択として文字・アイコンを描かせる。チェック項目は、メニュー内（`widget` が `QMenu`）のチェックボックス・ラジオの描画を印だけにする：オンなら文字色のチェックマーク（ラジオは点）、オフなら何も描かない。当初はチェックボックスの描画がそのまま使われ、非選択の項目では選択色の箱、選択中の項目では印だけになり、表示が揃わなかった（ユーザー報告、2026年10月7日） |
| スクロールバー（`CC_ScrollBar`） | 平らな溝（本文色3%）と、角丸の取っ手（30%、ホバー42%、押下55%）。両端の矢印はFusionの矢印を描く |
| タブ（`CE_TabBarTabShape`） | 平らな面（選択12%、ホバー9%、その他3%）と区切り線、選択中は内容側の辺に選択色の2px線。設定ダイアログのタブ、ドッカーのタブ群に適用。文書タブはフェーズ2のQSSが優先される |

選択方法: 「設定 → スタイル → Solstice」。保存先は既存の `widgetStyle`（値
`Solstice`）。`KisApplication` の起動処理と `KisMainWindow::slotUpdateWidgetStyle()`
が `KisSolsticeStyle` を生成して `qApp->setStyle()` に渡す（所有権はQApplication）。
Fusionを選べば元に戻る。

互換性の判断:
- スタイルの `objectName()` は "fusion" とし、`currentUnderlyingStyleName` も
  "fusion" にする。スピンボックスはこの名前で入力欄の位置を補正しており、
  寸法がFusionと同じなので同じ補正が正しい。
- 局所的なプロキシスタイル（レイヤー一覧の `LayerBoxStyle`、タグメニューの
  `KisMenuStyleDontCloseOnAlt`、最近使ったファイルのメニュー、色フィルターの
  コンボボックス、ストーリーボード）は、フェーズ3では
  `QStyleFactory::create(objectName)` で複製していたためFusionのままだった。
  フェーズ4で `KisSolsticeStyle::createStyle()` に置き換えた。
- 新しい設定項目は追加していない。

テスト: `libs/widgetutils/tests/KisSolsticeStyleTest.cpp`。スタイル名、Fusionとの
寸法一致（ボタン、トグル、ツールボタン、チェック、ラジオ、入力欄、コンボ、
スピン、スクロールバー、タブ、メニュー）、描画の実行、チェック付きメニュー項目
（選択中・非選択×チェック有無）の描画。`SOLSTICE_STYLE_DUMP=<dir>` で比較画像
`fusion.png`／`solstice.png`／`menu-fusion.png`／`menu-solstice.png` を保存する。`QT_QPA_PLATFORM=offscreen`
で実行できる（このときフォントは表示されない）。

確認事項（ユーザー）: スタイルの往復切替、テーマの切替、ボタン・入力欄・
チェック・ラジオ・メニュー・スクロールバー・タブの各状態、ツールボックスの
選択中ツール、ブラシエディターと設定ダイアログ、Quick Access等の独自UI。

### フェーズ4の実装（第1弾）

優先度: 使用箇所の多さと、フェーズ3の制限として残った箇所から選んだ。

| 対象 | 変更 | 実装箇所 |
| --- | --- | --- |
| スピンボックス（`CC_SpinBox`） | 入力欄と同じ角丸の枠（ホバー・フォーカスも同じ）。上下ボタンは枠の内側で平らにし、区切り線を入れ、ホバー12%・押下24%。矢印（プラス／マイナス表示も）はFusionの描画。押せない方向は無効色。寸法はFusionのまま | `KisSolsticeStyle::drawComplexControl()` |
| スライダー付きスピンボックス（`KisSliderSpinBox` 等） | 枠とボタンは `CC_SpinBox` で描かれるため上記と同じ外観になる。スライダーの塗りは従来どおり部品自身が描く | 変更なし |
| 局所プロキシスタイル5か所 | アプリのスタイルがSolsticeで、複製する名前が "fusion" のときはSolsticeスタイルを返す `KisSolsticeStyle::createStyle()` を使う。それ以外は従来どおり `QStyleFactory::create()` | `KisMenuStyleDontCloseOnAlt.cpp`、`krecentfilesaction.cpp`、`kis_color_filter_combo.cpp`、`LayerBox.cpp`、`StoryboardView.cpp`（各1行と include） |

局所スタイルは部品の作成時に複製するため、スタイルを切り替えた後に既に
作られている部品（レイヤー一覧等）は再起動まで前のスタイルのままになる。
これはFusion以外への切替でも従来から同じ。

テスト: `KisSolsticeStyleTest` に `createStyle()` の判定（アプリがFusionなら
Fusion、Solsticeなら "fusion" に対してSolstice、他の名前は工場の既定）を追加。
スピンボックスの寸法一致は既存の比較に含まれる。6件合格。

### フェーズ4の実装（第2弾）

設定ダイアログ: Solstice interface（`Solstice/ModernInterface`）が有効なとき、
`KisDlgPreferences` は `KPageDialog::Tree` を使う（無効時は従来の `List`）。
ページ一覧の `QTreeView` をコンストラクタの最後に調整する: ルートの装飾と
字下げなし、アイコン20px、項目の余白5／6px（QSS）、幅220px固定。従来の
Listは大きなアイコンの下に太字の名前を置き、メイン画面より大きく見えた。
オフスクリーン描画で両者を比較して決めた（比較用の一時テストは削除済み）。
設定はダイアログを開くたびに読むため、切り替え後に開き直すと反映される。

QML画面（テキストプロパティ等）: `KisQQuickWidget` はQuick Controlsの
Fusionスタイルを使い、ウィジェットのパレットを受け取り、
`KisConfigNotifier::signalColorThemeChanged` で更新する。QMLは
`palette.text` などを使うため、配色はSolstice Darkを含むテーマに追従済み。
形状（平らな角丸）をSolsticeスタイルに合わせるには独自のQuick Controls
スタイルが必要で、範囲外として制限に記録した。

フェーズ4の残り（未着手）: アイコンの線幅と大きさの統一（アイコン素材の
方針決定が必要）。

### UIフォント（Cantarell、2026年10月7日、ユーザー指示）

既定のUIフォントを同梱のCantarell（Regular／Bold／Italic／BoldItalic）にした。

| 部分 | 内容 |
| --- | --- |
| ファイル | `krita/data/fonts/`：TTF 4つ、`OFL.txt`（著作権表示とライセンス全文）、`fonts.qrc`、各TTFの `.license`（SPDX: OFL-1.1）。ライセンス本文は `LICENSES/OFL-1.1.txt` にもある |
| 埋め込み | `fonts.qrc`（プレフィックス `/solstice/fonts`）を `krita/CMakeLists.txt` の `krita_QRCS` に追加。Windowsでは `krita.dll` に入る |
| 登録 | `KisUiFont::registerBundledFonts()` が `QFontDatabase::addApplicationFont()` で登録する。`krita/main.cc` が `KisApplication::setFont()` の直前に呼ぶ |
| 既定値 | `KisUiFont::normalFont()` は、カスタムフォント（`use_custom_system_font`）が無効なとき、システムのUIフォントのサイズでファミリーをCantarellにする（登録できた場合のみ） |
| ライセンスの配布 | `krita/data/fonts/CMakeLists.txt` が `OFL.txt` を `share/krita/fonts/Cantarell-OFL.txt` にインストールする |

ライセンス: SIL Open Font License 1.1。ソフトウェアへの同梱・再配布は可。
著作権表示とライセンスを添える。Reserved Font Nameの指定はない。フォント
単体の販売と、改変版をOFL以外で配布することは不可。フォントは改変しない。

制限: 日本語などCantarellに無い文字はOSのフォントで表示される。カスタム
フォントが有効な設定（ユーザーの環境はSegoe UI）では、既定値は使われない。
テキストツールのフォント一覧（キャンバス上の文字）は変更していない。

### フェーズ2の具体的な変更

ドッカー見出しでは、背景・文字・ロック／分離／閉じるボタンの配置を整理する。
既存のドラッグ領域とボタンのクリック領域を保つ。

ドキュメントタブでは、選択中のタブを面と細い強調線等で示し、
閉じるボタン・省略表示・未保存状態が判別できるようにする。
既存のタブ用QSSと統合し、すべてのQTabBarへの一括適用を避ける。

ツールバーでは、アイコンの見かけの大きさ、区切り線、ホバー表示を整理する。
アクションの並び、ショートカット、ユーザーが保存した表示設定を維持する。

## 実装方針と候補箇所

配色は既存のテーマ機構を使い、テーマファイルを追加する。
QSSは対象を絞った試作と局所調整に使う。全アプリへの汎用セレクターで
余白・背景・フォントを一律に指定する方式は採用しない。
共通部品を継続的に調整する場合はQProxyStyleを検討し、変更しない描画は基底スタイルへ委譲する。

| 対象 | 調査・変更候補 | 留意点 |
| --- | --- | --- |
| 追加配色 | `krita/data/themes/` と同ディレクトリの `CMakeLists.txt` | 既存ファイルとテーマ名を上書きしない |
| テーマ通知 | `libs/ui/thememanager.cpp` | 配色変更とアイコンキャッシュ更新の順序を維持 |
| 起動・スタイル切替 | `libs/ui/KisApplication.cpp`、`libs/ui/KisMainWindow.cpp` | 起動時・切替時・新規ウィンドウで同じ見た目にする |
| ドッカー見出し | `libs/widgets/KoDockWidgetTitleBar.*`、`KoDockWidgetTitleBarButton.*` | 狭幅、浮動、ロック状態の既存処理を保つ |
| ドキュメントタブ | `libs/ui/KisMainWindow.cpp` のQMdiArea／QTabBar関連処理 | 閉じるボタン用QSS、フォント設定、タブ切替と共存 |
| 共通スタイル | 配置候補は `libs/widgetutils/` | 下位ライブラリから `kritaui` への依存を追加しない |
| アイコン | `libs/widgetutils/kis_icon_utils.cpp`、`krita/pics/` | リソース名、明暗切替、キャッシュの互換性を維持 |
| 数値入力 | `libs/widgetutils/kis_slider_spin_box.*` | ドラッグ・直接入力・ホイール操作を保つ |
| QML | `plugins/tools/svgtexttool/`、`plugins/dockers/textproperties/` | WidgetsのQSS適用を前提にしない |

既存の `KisMenuStyleDontCloseOnAlt`、最近使ったファイルのメニュー、
色フィルターコンボボックスには局所的なQProxyStyleがある。
新しいスタイルを重ねる際は基底スタイルの名前、所有権、再生成、破棄順を確認する。
一つのスタイルインスタンスを複数の所有者へ渡したり、切替ごとにラッパーを重ねたりしない。

Fusion採用は現時点では候補であり、既存のBreeze利用を強制的に変更しない。
Qtやスタイルプラグインの更新・追加導入は、本計画の前提にしない。

## 設定と互換性

既存の `Theme` と `widgetStyle` の値を読み続ける。
外観調整の新しい設定が必要な場合のみ `Solstice/` 配下に追加し、
未設定時は従来の外観を維持する。初回導入では新しい外観を選択式にする。

既存のドッカーID、アクション名、ワークスペース、ショートカット、
ウィンドウ配置、文書形式とそのシリアライズ内容は変更しない。
Quick Access、Rest Note、Asset Libraryのネイティブ構成と旧設定互換性を保つ。
各機能を変更するときは、先に対応するエージェント文書を全文確認する。

外観の切替ではテーマ通知を既存の経路に統合し、常時ポーリングや
見た目のためのグローバル入力イベントフィルターを追加しない。
複数ウィンドウ、新規作成、破棄時のライフサイクルを検証する。

## 検証と完了条件

実装時は、Windowsの100%・150%・200%表示で、追加テーマと既存の暗色・明色テーマを確認する。
利用可能な対象スタイルごとに比較し、OSが描画するネイティブダイアログは別に記録する。
Linux・macOSはビルド互換性を維持し、実機確認ができない場合は未検証範囲として明示する。

| 分類 | 必須確認 | 合格条件 |
| --- | --- | --- |
| 可読性 | 通常・ホバー・押下・選択・フォーカス・無効状態、日本語長文 | 文字の欠け、重なり、背景との同化がない |
| 配置 | 小さいウィンドウ、狭いドッカー、高DPI | 部品が操作不能にならず、不要な固定寸法で領域を消費しない |
| テーマ | テーマ変更、スタイル変更、アプリ再起動 | 部分的な旧配色や古いアイコンが残らない |
| ドッカー | 移動、分離、再結合、タブ化、ロック、ワークスペース復元 | 既存と同じ操作と復元結果になる |
| タブ | 切替、並べ替え、閉じる、未保存確認、複数ウィンドウ | 誤操作や未保存表示の消失がない |
| 入力 | Tab移動、メニュー操作、数値編集、ドラッグ、ホイール、ペン | フォーカス競合や押下・解放の不整合がない |
| カスタム機能 | Quick Access、Rest Note、Asset Library、Puppet Warp | 既存の操作と表示が維持される |
| 性能 | 起動、ドッカーのリサイズ、テーマ切替、描画中のUI操作 | 再現性のある新しい停止・ちらつき・遅延がない |

性能は同じ環境・文書・操作で変更前後を比較する。
遅延が疑われる箇所を計測し、通常のばらつきと区別できる悪化は解消してから次段階へ進む。
見た目だけの変更を確認するために実装をなぞる単体テストは追加しない。
新しい設定分岐や状態管理を導入する場合は、互換性・切替・破棄を対象に必要なテストを追加する。
コンパイル成功だけで入力操作や表示の確認を完了扱いにしない。

## ビルドと導入

実装は `krita-sol-gpu` 上で行い、既存の未コミット変更を保持する。
今回の文書作成ではビルドもインストールも行わない。

実装時は [開発手順](development-workflow.md) のビルド・テスト・インストール手順に従う。
同文書の古いブランチ・上流同期の記載より、ルートの `AGENTS.md` を優先する。

- C++は指定のclang-formatで整形する。既存ファイルは変更行のみを対象とする。
- 対象ファイルに `git diff --check` を実行する。
- `libs/widgetutils`、`libs/widgets`、`libs/ui` を変更した場合は、対応する
  `kritawidgetutils`、`kritawidgets`、`kritaui` をビルドし、変更した共有ライブラリをインストールする。
- テーマを追加した場合はCMakeを再構成し、テーマのインストール処理で配置を確認する。
  埋め込みアイコンを変更した場合は、そのQRCを所有するターゲットも再ビルドする。
- DLL更新後はアプリを完全に再起動する。実行中プロセスは無断終了せず、
  インストールがロックされたときはユーザーに終了を依頼する。

実際に外観の変更を導入する段階で `docs/ui-modernization.md` にユーザー向けの
切替方法、対象範囲、比較画像、制限事項を記載する。本書にも実装状況と確定仕様を反映し、
`docs/agent/feature-inventory.md` に実際の変更箇所を追加する。
READMEには利用可能になった機能名とユーザー文書へのリンクを追加する。

## 問題が見つかった場合の戻し方

追加配色は既存テーマへ戻して解除できるようにする。
形状・余白の変更は追加テーマとは独立した選択肢で無効化できる設計とし、
既存の `widgetStyle` と設定を保持する。切替に再起動が必要ならUIと文書に明記する。

ソースの修正を取り消す必要がある場合は、その段階で追加した変更だけを対象にする。
作業ツリー全体のリセットや既存ユーザー変更の巻き戻しは行わない。
QMLや独自部品の一部で統一できない箇所は制限として記録し、
対応範囲を絞った状態で段階を完了できるか判断する。
